Advanced commands

api-exploit, tr069-exploit, uart-at, config-decrypt, SMS, USSD and power controls.

api-exploit

research

Performs the exact S20_1.12.7 login sequence, runs a concurrent goformId sweep and optionally fuzzes unlock-related parameter names. Every response that is not {'{"result":"failure"}'} is reported as a hit, including unexpected HTML or error bodies — these often reveal undocumented endpoints. All POSTs go to /reqproc/proc_post as form data; reads use /reqproc/proc_get. The CSRFToken is sent in the form body and as a header, exactly as service.js does.

./zlt_xloader --dry-run=false --yes api-exploit --fuzz --fuzz-max 300 --workers 8
--username / --passwordWeb UI credentials (default admin/admin).
--outputWrite detected hits to a JSON file.
--include-builtinMerge the verified corpus from service.js.
--ratePer-worker delay, for example 50ms.
--fuzz / --fuzz-onlyGenerate additional goformId candidates.
--fuzz-maxBound the number of generated requests.
--fuzz-keywordsComma-separated keyword list for the generator.
--workersConcurrent worker count (default 16, capped at 256).
--token-sequenceUse the older set_random/get_random/set_token experiment.
Fuzzing can brick the device

Generated payloads may write NVRAM. Keep dry-run active while exploring, and only enable it on hardware you can afford to lose.

tr069-exploit

research

A local ACS simulator. The router is pointed at your machine, sends a SOAP Inform, and the tool replies with an InformResponse. On the next CPE request it pushes a SetParameterValues, Download or Reboot RPC. SOAP envelopes use the correct CWMP namespaces and XML escaping. The stock ACS is acs.slt.lk, which means the device can be managed remotely. --set-acs changes that URL from the local machine.

./zlt_xloader --dry-run=false --yes tr069-exploit --set-acs --rpc set-params --param InternetGatewayDevice.ManagementServer.URL --value http://192.168.1.2:7547/acs
--rpcRPC to push: set-params, download or reboot.
--param / --valueParameter name and value for set-params.
--serve-fileLocal file to serve for a Download RPC.
--set-acsPush the local ACS URL with setTR069Config and restart TR-069.

uart-at

hardware

Serial/UART interface for raw AT commands such as AT^NVW and AT+CLCK="PN",0. The engine uses send/expect semantics with timeouts and needs physical access, but does not depend on the locked web API.

./zlt_xloader uart-at --port COM3 --script
--listList available serial ports.
--portSerial port to open.
--scriptPreview the scripted AT sequence without opening the port.
--simulateRun against an in-memory mock serial device.
--command / --expectSend one raw command and check for an expected reply.
3.3V TTL only

The router's serial header uses 3.3V TTL logic. Do not connect an RS232 adapter (plus or minus 12V) — it will destroy the board. Pinouts vary by board revision, so trace them before probing. See Hardware notes.

config-decrypt

offline

Parses config.bin as a container with a header, payload and trailing signature. A per-block Shannon-entropy report separates structured data from encrypted or compressed regions. Candidate keys are derived from profile constants, the device serial and IMEI, then tried against common embedded algorithms (xor, xor-add, AES-CBC, DES-CBC) with a zero IV. Results are ranked by an entropy/printability score.

./zlt_xloader config-decrypt --file ./config.bin --top 10 --serial <SERIAL> --imei <IMEI>
--filePath to the config.bin container.
--topNumber of candidate keys to report.
--serial / --imeiDevice identifiers used as key material.
--key / --algoDecrypt with a known key and algorithm.
--outOutput file for decrypted data.

Messaging and power

# SMS
./zlt_xloader --dry-run=false sms list
./zlt_xloader --dry-run=false sms send --to 0771234567 --message "hello"

# USSD
./zlt_xloader --dry-run=false ussd --code '*#123#'

# Power (destructive — confirmation required)
./zlt_xloader --dry-run=false --yes power reboot
./zlt_xloader --dry-run=false --yes power off

sms lists stored messages or sends one. ussd sends a USSD code and reads the response. power reboots or powers off the device and requires explicit confirmation.
