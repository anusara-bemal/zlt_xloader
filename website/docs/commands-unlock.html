Unlock & optimise

unlock, unhide and optimize — removing carrier-imposed restrictions and tuning the connection.

unlock

mutating

Uses the same REMOVE_WHITE_SITE injection as telnet to run nv set commands as root. It clears tz_lock_plmn_state, tz_lock_plmn_list, tz_lock_band_state, tz_lock_3G_band_state, tz_lock_imsi_state, use_lock_net and tz_lock_sim, then runs nv save and patches the default parameter files so the change survives a factory reset. A backup of the original NVRAM is written to /tmp/zlt_xloader-nv-backup.txt on the router. Verify with nv get tz_lock_plmn_state over a shell — it should print no.

./zlt_xloader --dry-run=false --yes unlock --reboot
--rebootReboot after clearing the lock state.

unhide

mutating

The SLT/Dialog firmware hides pages with three NVRAM bitfields: tz_web_page_hide, tz_web_user_hide and tz_web_special_func, plus feature flags such as need_support_sms and need_support_ussd. This command clears the hide bits and enables the flags so SMS, network selection, APN and other pages appear in the web UI. The backend endpoints are present even while the pages are hidden.

./zlt_xloader --dry-run=false --yes unhide --reboot
--rebootReboot so the web UI reflects the new flags.
Firmware quirk

config.js on the S20_1.12.7 build has HAS_USSD:false, so the USSD page may not render even after the flags are enabled. The API itself still responds.

optimize

mutating

Prints live RF diagnostics — band, bandwidth, RSRP/RSRQ/SINR, PCI and SIM PLMN — then applies what the router actually controls: DNS 1.1.1.1 / 8.8.8.8, data-volume cap and quota alerts off, QoS off, and no band lock.

./zlt_xloader --dry-run=false --yes optimize --reboot
--rebootReboot after applying the settings.
Limits of optimisation

Carrier-core latency from CGNAT or roaming cannot be changed from the router. On the reference device the RF link was already healthy (Band 3, 20 MHz, SINR around 19 dB), so remaining latency was in the operator's network rather than the air interface.
