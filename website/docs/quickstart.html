Quickstart

A safe first session — fingerprint the router, inspect state, and preview a change before applying it.

Before you begin

Connect the router to your machine and make sure you can reach its web UI. Everything below is read-only until the final, clearly marked step. Use a device you own.

1. Fingerprint the device

./zlt_xloader --target 192.168.1.1 scan

This reports open ports and the detected profile without changing anything:

Target: 192.168.1.1  (profile: Tozed ZLT S20 1.12.7 (Dialog / SLT-Mobitel))

  tcp/23     closed
  tcp/80     OPEN
  tcp/8080   closed
  tcp/7547   OPEN

  profile     Tozed ZLT S20 1.12.7 (Dialog / SLT-Mobitel)
  firmware    S20_1.12.7
  model       ZLT S20
  acs_url     http://acs.slt.lk:7547/
  dry_run     true

A custom port list is available with scan --ports 23,80,8080,7547,443.

2. Read the live state

./zlt_xloader status

status reads NVRAM through a shell, so it reports the real lock state even when the web API returns empty values.

3. Preview the web API behaviour

./zlt_xloader api-exploit

With dry-run active, the login flow, token request and payload sweep are printed but not sent. This is the safest way to learn which goformId values your firmware responds to.

4. Preview a mutating command

./zlt_xloader telnet

The tool prints the command chain it would use to start telnetd, including the hash/Base64 encoding and isTest=false handling. Nothing is written yet.

5. Apply a change (optional)

Only when you have verified the target and accepted the risks:

# Start a root shell on port 23
./zlt_xloader --dry-run=false telnet

# Confirm and verify
./zlt_xloader status

The telnetd started this way is runtime-only. After a reboot, rerun the command — or use persist to start telnet and SSH at every boot, which backs up /etc/rc first.
