Tozed ZLT S20 · security research

One binary.
Four ways in.

zlt_xloader is a profile-driven toolkit for the Tozed ZLT S20 4G router. Read the firmware, reach a root shell, take over the TR-069 channel or talk to the serial console — with a write gate that refuses to touch the device until you say so.

01 / MODEL

Four ways into the same router

Each path reaches the device independently. Start with the read-only one, then move down only as far as you need to.

01

Web API

The Tozed endpoints behind the web UI. Login is the exact get_random_login → LOGIN → get_token sequence from the firmware's own JavaScript, including the hash and CSRF handling. A bounded worker pool sweeps goformId values and reports anything that is not the canonical failure body.

PORT / 80scan · api-exploit · status
verified corpus + reported IDs
rate-limited workers
02

Root shell

A command injection in the ids field of REMOVE_WHITE_SITE starts telnetd on port 23. SSH is available through shell --ssh, and persist writes a boot block (after backing up /etc/rc) so both ports return after a reboot.

PORT / 23 · 22telnet · shell · persist
runtime or persistent
download via local HTTP
03

TR-069 management channel

The stock ACS is remote, which means the router can be managed by someone else. tr069-exploit turns this machine into the ACS: it answers the SOAP Inform, then pushes SetParameterValues, Download or Reboot on the next CPE request.

PORT / 7547tr069-exploit
local ACS simulator
correct CWMP envelopes
04

Serial console

When the software path is locked, the hardware path remains. uart-at opens a 3.3V TTL serial line and runs scripted AT commands with send/expect semantics — no dependency on the web API.

02 / SAFETY
The write gate

Nothing reaches the device by accident

Every mutating command has to pass the same sequence. This is the part of the design that matters most on hardware you cannot replace.

01 / observeRead first

scan and status never write. Fingerprint the firmware before forming a plan.

02 / defaultDry-run

Mutations start with --dry-run=true. You see the exact commands or RPCs instead of an applied change.

03 / opt inExplicit flag

Writing requires --dry-run=false. There is no implicit "yes" anywhere in the tool.

04 / confirmConfirm

Destructive RPCs, NVRAM writes and UART commands ask interactively, or need --yes.

05 / recoverBack up

unlock saves NVRAM to /tmp/zlt_xloader-nv-backup.txt; persist copies /etc/rc.

Profile constants can be corrected from a packet capture without recompiling — but a wrong value can still brick the device. There is no warranty.

03 / COVERAGE

Known firmware variants

The default profile targets the Dialog / SLT-Mobitel build. Two more ship with their own fingerprint commands, payload sets and unlock keys.

Profile fileFirmwareVariantNotes
zlt_s20_1.12.7.jsonS20_1.12.7Dialog / SLT-MobitelVerified against service.js. Default profile.
zlt_m910w_1.13.6.jsonS20_1.13.6MTNVariant-specific unlock parameters.
zlt_s20_1.02.7.jsonS20_1.02.7ORGVariant-specific fingerprint and NVRAM keys.

Standard ZTE tooling does not work on this hardware — Tozed uses a different web API. If your build is not listed, copy a profile, mirror the observed parameter names from a capture, and pass it with --profile. See the profile guide.

Common workflows

preview first
Read-only
./zlt_xloader --target 192.168.1.1 scan
./zlt_xloader scan --ports 23,80,8080,7547,443
./zlt_xloader status
Root shell
./zlt_xloader shell
./zlt_xloader shell --command "nv get sim_plmn"
./zlt_xloader shell --at --command "AT+CSQ"
./zlt_xloader --target 192.168.1.1 shell --ssh

Telnet is enabled automatically if port 23 is closed. Use persist to start telnet and SSH at every boot.

Preview, then apply
./zlt_xloader unlock
./zlt_xloader --dry-run=false --yes unlock --reboot
./zlt_xloader --dry-run=false --yes persist --reboot
./zlt_xloader --dry-run=false --yes unhide --reboot

NVRAM and the boot script are backed up on the device before these commands write.

Local ACS
./zlt_xloader tr069-exploit --rpc set-params \
  --param InternetGatewayDevice.ManagementServer.URL \
  --value http://192.168.1.2:7547/acs

./zlt_xloader --dry-run=false --yes tr069-exploit \
  --set-acs --rpc reboot
Other profiles
./zlt_xloader --profile ./profiles/zlt_m910w_1.13.6_mtn.json scan
./zlt_xloader --profile ./profiles/zlt_s20_1.02.7_org.json status
./zlt_xloader uart-at --list
./zlt_xloader config-decrypt --file ./config.bin --top 10

UART is 3.3V TTL only. Read the hardware notes before connecting an adapter.

06 / BOUNDARY

Educational use, owned hardware only

These are the terms the project is built around. Read them before running a mutating command.

Read this first

This tool is for devices you own

Use it only for lawful security research on hardware you personally operate, or a device you are explicitly authorised in writing to test. Unlocking a carrier lock may breach your contract or local law. Modifying firmware can permanently brick the device and void its warranty. There is no warranty, and the authors are not liable for misuse.

  • Dry-run default — --dry-run=true until you opt out.
  • Confirmation — destructive operations prompt or require --yes.
  • Backups — NVRAM and /etc/rc saved before writes.
  • 3.3V TTL only — an RS232 adapter will destroy the board.
  • No telemetry — all traffic stays on your local network.

07 / NOTES

Before you flash anything

Short answers to the questions that come up most often.

Q1

Is this legal?

It is intended for lawful research on devices you own or are authorised to test. Check your jurisdiction before attempting to remove a carrier lock.

Q2

Will it work on my router?

The shipped profiles cover S20_1.12.7 (Dialog / SLT), S20_1.13.6 (MTN) and S20_1.02.7 (ORG). Run scan first to fingerprint your device.

Q3

Does it change anything by default?

No. Mutations default to --dry-run=true, and destructive operations require confirmation.

Q4

Does telnet survive a reboot?

No. telnet starts a runtime daemon only. Use persist for boot-time telnet and SSH, or rerun the command.

Q5

Why not standard ZTE tooling?

Tozed uses a different web API. This tool implements the Tozed login/CSRF flow and targets those endpoints directly.

Q6

Can I add my firmware?

Yes — copy a profile and mirror the parameter names from a packet capture. Never commit personal data. See the profile guide.
